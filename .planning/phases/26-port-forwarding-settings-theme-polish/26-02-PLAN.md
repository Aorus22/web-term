# Plan 26-02: Settings Page & Live Mid-Session Theme/Palette Sync

## Frontmatter
- **Phase:** 26-port-forwarding-settings-theme-polish
- **Plan:** 26-02
- **Requirement:** SET-01 (User can configure themes and desktop preferences; no terminal engine selector — fixed to alacritty; live theme change applies to app and terminal palette live mid-session)
- **Status:** Ready

## Objective
Implement desktop settings and live mid-session theme synchronization:
1. Extend `TerminalView` in `webterm-terminal` with `set_palette(&mut self, palette: ColorPalette, cx: &mut Context<Self>)` to support dynamically updating color palettes on active terminal sessions.
2. Update `AppState` in `webterm` so that changing themes:
   - Updates `self.theme` and persists to `DesktopSettings`.
   - Calls `crate::theme::apply_theme(self.theme, cx)` to update GPUI components.
   - Propagates the corresponding `ColorPalette` (`dark_default()` or `light_default()`) across all active terminal tabs in `self.session_manager.sessions_mut()`.
3. Redesign `views/settings.rs`:
   - Theme selection cards (Dark, Light, System) with active state badge.
   - Desktop Preferences: backend path override display and editing (custom path vs bundled default) with "Reset to Bundled" action.
   - Font size preference for terminal rendering.
   - Informational card for Terminal Engine: states that the desktop engine is permanently fixed to native Alacritty Terminal (Zed-proven, GPU-accelerated, zero browser overhead). Strictly NO dropdown or engine selector (complying with SET-01).
   - Backend service process status indicator.
4. Add unit and integration tests:
   - `desktop-gpui/crates/terminal/tests/palette_update_test.rs` validating dynamic palette swapping on `TerminalRenderer` and `TerminalView`.
   - `desktop-gpui/crates/webterm/tests/settings_theme_test.rs` validating settings persistence, theme toggle, and terminal palette propagation.
